# Google 캘린더 선택 연동

배포 앱 사용자는 **설정 → Google 캘린더 → Google로 로그인**에서 Google의 권한 동의 화면을 열어 연결합니다. 개인별 OAuth 프로젝트 생성, JSON 파일 선택, 토큰 복사, 개발 도구 설치는 요구하지 않습니다. 연결 해제와 자동 반영 중지를 지원합니다. 스티커 메모와 디스플레이 배치 기능은 사용자 요청에 따라 구현하지 않습니다.

캘린더는 기본 꺼짐이며 최초 설정에 포함되지 않습니다. 사용자가 원할 때만 설정에서 연결하고 **Google 캘린더로 마감 받기**를 켜거나 끕니다. 꺼짐 선택은 앱을 다시 실행해도 유지되며 LMS 확인과 Discord 알림에는 영향을 주지 않습니다. Google 연결 없이 초기 설정을 완료할 수 있습니다.

서비스용 Google 로그인 등록값이 없는 배포본에서는 로그인 버튼이 비활성화됩니다. 대기로 해결되지 않으며 설정이 반영된 배포본이 필요합니다. preview.3부터 비활성 상태는 로딩 포인터 대신 사용 불가 포인터로 표시하고 이유를 본문과 툴팁에 안내합니다.

## 동작과 자원 사용

- preview.5부터 정상 수집된 전체 과제·강의 목록에서 사라진 항목은 이미 등록한 일정에 **⛔ 삭제**를 표시하고 팝업 알림을 해제합니다. 영구 삭제 대신 기존 날짜와 기록을 유지하며, 같은 항목이 다시 나타나면 현재 LMS 상태로 복원합니다. 과목 접근 실패·메뉴 없음·수집 오류·식별 불가 강의가 포함된 목록은 삭제 근거로 사용하지 않습니다. 앱이 만든 일정 표식을 확인한 뒤에만 갱신하며, Google에서 이미 지운 일정을 삭제 표시를 위해 새로 만들지 않습니다. 연동 OFF 동안에는 삭제 반영도 중지하고 다시 켰을 때 반영합니다. LMS가 숨긴 항목과 교수자가 실제 삭제한 항목은 목록만으로 구분할 수 없으므로 표시 설명에는 ‘삭제·제외’라고 안내합니다.

- 별도 서버, Google SDK, 상주 프로세스, 10분 폴링, Codex 자동화를 추가하지 않습니다. 기존 LMS 확인 프로세스에서만 동작합니다.
- Google 로그인은 토큰 발급 후 기본 캘린더의 소유자 접근까지 확인해야 성공으로 처리합니다. 저장된 연결은 앱 재실행 시 재로그인 없이 검수하며, 실패해도 LMS/Discord 시작을 막지 않습니다. 설정의 **연결 검수 · 기존 마감 반영**으로 다시 확인할 수 있습니다.
- 연결 직후 저장된 최신 LMS 수집 결과의 미제출 과제·미수강 강의 마감을 기본 캘린더에 등록합니다. 새 Discord 알림 유무와 무관하게 기존 항목도 반영합니다. 이후 LMS 확인에서 신규 마감과 변경을 갱신합니다. 공지·자료·기한 불명 항목에는 마감을 추정하지 않습니다.
- 날짜만 있으면 종일 일정으로, 시간이 있으면 정확한 마감부터 1분 동안의 일정으로 표시합니다. 일정은 바쁨 시간을 차지하지 않으며 한 시간 전 팝업 알림을 설정합니다. 종일 일정의 팝업 시각은 Google의 종일 일정 처리 기준을 따릅니다.
- 항목별 안정된 이벤트 ID와 로컬 반영 기록을 사용해 D-7/D-3/D-1/D-Day를 하나의 일정으로 유지합니다. 변경 없는 반복 알림에서는 토큰 갱신과 Calendar API 호출이 모두 0회입니다. 마감·제목 변경은 기존 일정을 갱신합니다.
- LMS에서 과제 제출 또는 강의 수강/출석 인정 완료가 명시적으로 확인되면 같은 일정에 **✅ 완료**를 표시하고 팝업 알림을 끕니다. 출석 인정과 전체 시청 완료는 설명에 구분합니다. 상태 불명이나 수집 실패를 완료로 추정하지 않습니다. 명시적 미완료로 돌아오면 완료 표시를 해제합니다.
- 새 작업이 있는 실행당 토큰을 한 번만 갱신하고 최대 20개 일정을 순서대로 처리합니다. 실패는 다음 LMS 확인으로 이월하며 Retry-After를 존중합니다. 권한 오류는 재로그인 전까지 중단합니다.
- Google 실패로 Discord를 재전송하지 않습니다. 로그인 정보와 Google refresh token은 사용자별 Windows Credential Manager에 저장하며 access token은 현재 실행의 메모리에서만 사용합니다.
- 해제 후 이미 만든 일정을 삭제하지 않습니다. 이미 기한이 지난 항목도 현재 미완료로 확인되면 초기 반영합니다. 처음부터 완료된 항목이나 최근 수집에서 확인되지 않은 항목은 새 일정을 만들지 않습니다. 직접 삭제한 완료 일정은 복원하지 않습니다. 재연결 후 완료 갱신은 대상 Google 캘린더의 기존 알리미 일정 소유 표식을 확인한 뒤에만 수행합니다.
- 연동 오류는 설정과 대시보드의 경고로 표시합니다. 토큰 만료, 캘린더 권한 부족, 서비스 API 미활성화, 네트워크 문제, 요청 한도를 구분합니다. 로그인 검수는 일정 내용을 조회하거나 시험 일정을 만들지 않습니다.

## 운영자 최초 설정 — 배포 전에 한 번

1. 서비스 소유자의 Google Cloud 프로젝트에서 Google Calendar API를 활성화합니다.
2. Google Auth Platform에서 앱 이름, 지원 연락처, 서비스 홈페이지, 개인정보처리방침, 필요한 도메인과 동의 화면을 설정합니다. 이용자에게 캘린더에 저장하는 정보와 연결 해제 방법을 안내합니다.
3. OAuth 클라이언트 유형을 **데스크톱 앱**으로 등록합니다. 이 앱은 시스템 브라우저와 `127.0.0.1`의 임시 loopback 포트를 사용합니다. 웹 앱 클라이언트, 서비스 계정, API 키를 대신 사용하지 않습니다.
4. `https://www.googleapis.com/auth/calendar.events.owned` 권한을 설정하고 Google이 요구하는 프로덕션 게시 및 검증 절차를 완료합니다. 테스트 모드는 테스트 사용자와 토큰 만료 정책의 제약이 있으므로 일반 배포의 완료로 취급하지 않습니다.
5. 릴리스 빌드 환경에서 `HS_LMS_GOOGLE_CLIENT_ID`, `HS_LMS_GOOGLE_CLIENT_SECRET`을 주입합니다. 둘은 해당 데스크톱 클라이언트의 등록값입니다. 데스크톱 앱에 포함된 client secret은 기밀을 보장할 수 없으므로 인증 코드는 PKCE와 state 검증으로 보호합니다. 서버용 confidential client secret이나 사용자 refresh/access token은 빌드에 넣지 않습니다.
6. Google 로그인을 제공하는 릴리스는 `HS_LMS_REQUIRE_GOOGLE_LOGIN=1`도 지정하고 `npm run dist:win`을 실행합니다. 등록값이 빠지면 빌드가 실패합니다. 환경변수는 릴리스 프로세스에서만 주입하고 사용자에게 설정을 요구하지 않습니다. `gui-build.ts`는 `.env`를 자동으로 읽지 않습니다.
7. 운영자가 실제 계정 로그인, 최초 등록, 중복 방지, 마감 변경, 앱 재실행, 토큰 갱신, 접근 철회 후 재연결을 검증한 뒤 배포합니다.

등록값 없는 개발 빌드는 Google 로그인 버튼을 비활성화하고 미지원 상태를 표시합니다. 기존 LMS/Discord/예약 중단/관심영역 기능은 사용할 수 있습니다. 현재 제공하는 preview는 이 상태이며 실제 Google 계정과의 연동 검증은 아직 수행하지 않았습니다.

## 검증

`npm run typecheck`, `npm test`, `npm run gui:test`를 사용합니다. Calendar API 및 토큰 응답은 합성 데이터로 대체하며 OAuth callback은 로컬 loopback에서 state·PKCE·취소·종료를 검증합니다. 실제 Google 토큰과 사용자 일정은 테스트에 사용하지 않습니다.

`npm run calendar:doctor`는 실제 저장된 Google 로그인과 기본 캘린더 접근을 읽기 전용으로 점검합니다. 계정 식별자·토큰·일정 내용은 출력하지 않습니다. `NOT_CONFIGURED`는 연결 전으로 실계정 검수 미완료, `FAILED`는 검수 실패, `PASSED`는 기본 캘린더 접근 확인을 뜻합니다. 이 명령의 접근 확인만으로 일정 쓰기 검수까지 완료했다고 판정하지 않습니다.
