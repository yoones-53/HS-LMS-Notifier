# Discord 알림

루트 `.env`의 `DISCORD_WEBHOOK_URL`만 사용한다. 코드/로그/DB에는 URL이나 토큰을 저장하지 않는다. 공식 HTTPS Webhook 주소만 허용하고 리다이렉트는 따라가지 않는다. [Discord 공식 Webhook 문서](https://docs.discord.com/developers/resources/webhook#execute-webhook)의 `wait=true`로 메시지 생성 확인을 받고, [공식 rate limit 안내](https://docs.discord.com/developers/topics/rate-limits)에 따라 429 응답은 지정된 시간 이후로 보류한다.

`npm run notify:test`: 최초 연결 테스트 1개. 같은 DB에서 재실행하면 SKIPPED.
`npm run notify`: DB의 미전송 변경 이벤트를 최대 20개씩 순서대로 전송한다. 과거 baseline은 이벤트가 없으므로 보내지 않는다. 동기화만 하는 `npm run sync`와 구분한다.

내용은 간단한 Embed로 과목, 제목, 가능한 마감/상태를 표시한다. 멘션을 비활성화하고 동적 텍스트를 제한/이스케이프한다. 실제 상세 주소가 공통 POST 방식이어서 확인되지 않은 deep link 대신 LMS 강좌 목록 링크를 제공한다.

## 중복과 실패 처리

- DB notification_history에 고유 알림 키를 먼저 SENDING으로 확보한다.
- 성공은 SENT로 남기고 같은 키를 다시 보내지 않는다.
- 명확히 거절된 4xx/429는 RETRY로 보류한다. 한 실행에서 반복 요청하지 않는다.
- 네트워크 timeout/5xx/불완전 응답은 이미 전달됐을 가능성이 있어 UNKNOWN으로 남기고 자동 재전송하지 않는다.
- 전송 직후 프로그램이 종료돼 SENDING으로 남은 경우도 자동 재전송하지 않는다. Discord 수신 여부와 로컬 상태를 확인한 후 사용자의 명시적인 재시도 요청이 필요하다.
- 따라서 일반적인 반복 실행의 중복은 막지만, 네트워크·프로세스 장애 사이의 완벽한 exactly-once 전달은 보장하지 않는다. 불명확한 전송은 중복보다 누락 위험을 택하고 확인 필요 상태로 기록한다.

## 11단계 검증

사용자가 URL 입력 완료를 알린 후 형식 유효성만 확인했다. 실제 테스트 명령 첫 실행 SENT, 두 번째 SKIPPED. 실제 pending 이벤트가 0개인 상태에서 notify를 두 번 실행해 0건 전송 확인. 공지/과제 신규 이벤트의 실제 detector→SQLite→전송기 연결과 반복 실행은 외부 전송 없는 주입형 transport 테스트로 검증했다. 비밀값은 출력하지 않았다.

## D-Day

한국 달력 날짜 차이가 7/3/1/0이고 실제 마감 시각 전인 과제/온라인 강의만 대상이다. 제출 완료 과제와 LMS 출석완료 영상은 제외한다. 진도율/전체 시청 여부는 미확인으로 표시하며 임의로 완료 판정하지 않는다. 날짜 파싱 실패는 알림에서 제외하되 다른 항목 처리는 계속한다. 마감이 연장돼도 동일 항목/동일 D-Day는 재전송하지 않는다.

알림 키는 항목과 D-Day 기준의 조합이다. 마감 변경은 별도 변경 이벤트로 알린다. 통합 실행은 최초 baseline 유형의 마감 알림도 억제하고 이번 수집 성공 항목만 사용한다. 실패한 유형의 DB에 남은 과거 제출 상태로 알리지 않는다. 4개 알림 기준과 한국 자정 경계, 미확인/완료/지난 항목 및 반복 전송은 합성 테스트로 검증했다.

## 운영 상태

최초 정상 자동 로그인·전체 동기화 후 연동 요약을 1회 보낸다. 기존 baseline 사용자도 INITIAL_SETUP_SUMMARY/SENT 이력이 없으면 대상이다. 일반 변경 이벤트와 별도 키를 사용하며 상태/계산/실패 재시도 정책은 `initial-summary.md`에 기록했다.

`npm run check`가 현재 과목의 변경 이벤트와 D-Day를 순서대로 보낸다. 변경 알림/마감 알림은 각각 실행당 최대 20개이며 1.1초 간격이다. rate limit/전송 확인 불가 시 해당 묶음을 중단하고, 변경 알림이 보류되면 그 실행의 마감 알림도 보내지 않는다. 보류 중 마감 알림은 이후 실행에서도 기준 날짜/완료 상태가 맞는 경우에만 재검토한다. 실행을 놓친 과거 D-Day를 소급 전송하지 않는다.

Scheduled Fresh Login 전환 후에는 AUTO_LOGIN_FAILED/AUTO_LOGIN_REQUIRES_USER/CREDENTIALS_NOT_CONFIGURED/AUTH_EXPIRED_DURING_CRAWL을 구분한다. 종류별 문제가 지속되는 기간에 1회만 알리고 정상 인증·강좌 확인 뒤 기간을 끝낸다. 알림은 고정 설명과 복구 명령만 포함하며 ID/PW·원시 로그인 응답은 포함하지 않는다. 기존 notification_history는 삭제하지 않는다.

인증 만료는 현재 만료 기간의 고유 키로 한 번 보낸다. 인증 확인이 성공하면 그 기간을 끝내고, 이후 다시 만료됐을 때 새 알림을 허용한다. 실제 예약 운영에서 인증 만료 및 D-Day 알림이 SENT로 기록되고 후속 정상 실행에서 반복 전송되지 않는 것을 확인했다. 계정별 실행·전송 수는 문서에 기록하지 않는다. 신규 공지/과제의 전달·중복 방지는 합성 transport 테스트로 검증했다.
